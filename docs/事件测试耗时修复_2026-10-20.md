# 事件测试耗时排查与修复

本次改动留在本地，未提交、未推送。保留工作区其他任务的修改和已暂存的园林工具清理。

实际瓶颈是测试中断后仍等超时。事件删字回调中有一段重复追加文案的代码，引用了不在当前作用域的 `index`，导致整个事件页编译失败。旧运行器一直等 Godot 退出，默认单套件可等待 180 秒；Windows 超时时只终止 console 启动器，实际游戏子进程还可能占着输出管道。没有测试结果但进程退出码为零时，旧运行器还可能显示通过。

修复内容：

- 去掉删字回调中的重复代码，保留选项结算处原有的追加文案逻辑。
- 运行器实时读日志，遇脚本错误立即中止并报告 ERROR；超时结束本次调用的进程树。Windows 默认直接调用主程序，减少 console 包装层。
- 每个套件开始时显示进度，保存完整日志。未输出测试结果不能算通过；整轮预算不足时返回未完成状态。
- 旧 `room_event_ui_test` 改走当前节点图、完整事件页和删字弹层，测试目录选项、待选状态和结算返回，不再打开标题、等待 3D 装配或访问已删除的抽屉控件。迁移后重新加入 event 分组。
- 事件测试关闭真实自动保存和成就写盘；仍保留各自显式使用的测试存档读写检查。

实测 `python tools/run_tests.py --group event --timeout 25 --budget 90 --strict`：

| 套件 | 检查数 | 耗时 |
| --- | ---: | ---: |
| event_system_test | 633 | 3.4 秒 |
| event_interaction_test | 43 | 12.1 秒 |
| event_reward_audit_test | 61 | 5.5 秒 |
| room_event_ui_test | 19 | 4.1 秒 |

四套件 756 项全部通过，合计约 25 秒。运行器另有 9 项检查，覆盖错误即时返回、超时清理、继承输出管道的子进程、正确结果统计和无结果退出；均通过。用真实 Godot console 启动器运行临时编译错误脚本，0.39 秒识别并结束，没有等待 15 秒限时。

事件专项建议使用 `python tools/run_tests.py --group event --timeout 30 --budget 90 --fail-fast`。`--changed` 会按整个工作区的所有改动选组，多个任务同时修改时可能扩展到 core、relic，不能把它当作事件专项。
